基于 `anlu_lr_turn_20261011` 复制建立的独立完整工程。当前升级用于稳定检测框及左右转指令。保留 1280×720、SC500CS、自动曝光、自动白平衡、板载显示切换和 FPGA—STM32 控制链路。

## 操作与显示

1. 加载新 bit，等待摄像头 AE/AWB 稳定。默认 RAW 模式下识别同时运行。
2. 正对完整蓝底白箭头圆牌，建议圆牌直径 100～300 个相机像素，保持片刻。
3. 首先显示黄色候选框、`DIR:?`。同一位置关联目标的匹配分数 ≥50、左右分数差 ≥12，并且连续三帧方向相同，才显示绿色框及 `DIR:L` / `DIR:R`。
4. 锁定后，框按目标位置与大小更新，方向保持首次确认的 L/R。即使 MATCH 降到 0 或逐帧匹配短暂指向相反方向，锁定方向也不改变。
5. MATCH 仍显示当前匹配分数，属于前景交并比，不是识别概率。绿色框表示已锁定，不能只看 MATCH 判断是否锁定。
6. 目标短暂被遮挡或消失，保留上次框及方向；连续丢失第八帧清除框和方向，恢复 `?`，重新开始搜索。重新找到关联目标时，丢失计数清零。
7. 要识别另一张路牌，先移走原目标，让框消失，再放入新牌；或者复位开发板。直接在同一位置替换另一张蓝色路牌会继续保留原方向，这是本版锁定规则。
8. KEY4 短按并释放切换 `RAW → ERO → DIL → SIG → RAW`；方向锁定与显示模式无关。KEY4 长按仍按小车慢速逻辑处理。

## 算法和指令链路

- 首次搜索使用蓝色游程候选，左右 16×16 模板分别从用户于 2026-10-12 提供的两张正式标识提取。两份模板使用与 RTL 一致的蓝/白阈值、4×4 采样、归一化和内部掩膜。
- 每帧选择与上次位置最接近的合格候选：宽高变化各不超过约 25%，中心移动不超过对应跨度的 1/4 加 16 像素。
- 未锁定时，如果没有关联候选，重新选择合格蓝色面积最大的目标，重置方向确认；不使用原目标得分给新目标赋方向。
- 锁定期间只允许关联候选更新位置；远处更大的蓝色区域不能抢占目标。
- 锁定与保留期间，检测器的 ASCII 方向、class、result_valid、HDMI 元数据均同步保持。小车决策模块使用的也是锁定方向，再按原协议编码为 STM32 速度包；单帧方向误匹配不会触发相反转向。
- 小车原三帧转向确认、停车/障碍/链路检查和电机闭环仍由现有 FPGA 控制逻辑与 STM32 执行。
- 不增加像素视频路径的寄存器级或 DDR 访问；新增计算发生在帧结束后的候选选择与结果发布阶段。

## 当前边界

- 本次同时完成目标/方向锁定，以及两张正式标识的独立模板。初次匹配门槛仍为 50，模板匹配分数不是实物准确率。
- 圆牌大小仍需约 64～512 相机像素，最多八个蓝色候选，只跟踪一个目标。
- 快速大幅移动、蓝色物体相连、被同位置相似蓝色物体替换，可能导致丢失或错误关联。位置和颜色跟踪无法独立验证同一物体的身份。
- 方向一旦确认便保持：初次连续三帧误判也会锁住，应移走目标等待清除或复位后重试。
- 保留时长以摄像头帧数计算，不是永久框住空背景。本版没有加入帧差法或去雾。
- 所有 Latin 字母、数字、冒号及问号统一 16×16 字格，采用同一 10×14 笔画尺度；标题计数数字取消独立拉伸。汉字保留原绘制尺寸。
- Logo 地址提前一拍计算和寄存，匹配坐标 1d→2d；RGB、同步信号和视频读取延迟不变。
- 参考标识原图、蓝色区域裁切、实际网格模板和 SHA-256 在 `sim/lr_turn/reference_20261012/`，复现脚本为 `prepare_reference_signs.py`。
- RTL 仿真不能代表实际摄像头准确率，上板后仍需验证距离、照明、运动和纸质/屏幕展示条件。
