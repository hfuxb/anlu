## 分工与保留功能

FPGA 在 SIG 中输出稳定的 L/R，连续三次结果确认后发一个带序号的相对角度请求。STM32 用经过校准的实际陀螺仪 Z 角速度积分角度，角度外环输出角速度，再经原四驱运动学和编码器轮速 PI 执行。轮速、车型选择、失能、低压及停车逻辑保留。

默认左转 +90°、右转 -90°，原地转向，最大角速度0.7rad/s。误差进入±1.5°并且实测角速度小于0.06rad/s连续200ms后报告 DONE；误差过大时重新修正。该容差是控制器设置，不是已经测得的实车精度。

AE/AWB、1280×720、识别锁定与十四帧丢失保持、Sobel→腐蚀→膨胀、MOT、DEH、右上角LAT保留。KEY4顺序仍是 RAW→ERO→DIL→MOT→DEH→SIG。只有SIG允许识别和视觉控制。

**转向触发仍是三次稳定识别结果，没有新增“到达路口才转”的距离/位置判断。** 本版也没有新增避障传感器。2026-10-13自动去雾升级已把KEY3改为AUTO／强制正常识别，顶层不再用它模拟障碍停车；停车使用KEY2。

## 配套文件和操作

- FPGA：`fpga/traffic_sign_td/td_project/bitstream/traffic_sign_td_lr_tracking_lock.bit`。另一个 `_compress.bit` 是同一设计的压缩配置，选一种即可。
- STM32：`stm32/WHEELTEC_C50X_FPGA_PD89/OBJ/cli_4WD/4WD_Car_FPGA_PD89.hex`，目标 **4WD_Car**，Flash地址 **0x08000000**。
- TD工程：`fpga/traffic_sign_td/td_project/traffic_sign_td.al`。
- Keil工程：`stm32/WHEELTEC_C50X_FPGA_PD89/USER/WHEELTEC.uvprojx`。

需同时更新这两个固件：新FPGA要求24字节常规遥测和新增11字节动作状态都新鲜；旧STM32固件没有新增状态，因此不能ARM。尚无小车时可以只验证FPGA图像功能。

1. 两板分别用原烧录工具加载上述配套文件，沿用TX/RX/GND接线：FPGA TX→STM32 PD9，FPGA RX←PD8。C50C V2.0 HDR2针号和供电说明见本目录README。
2. STM32上电后车体保持静止约13秒；第一次联调可等待15秒。10秒启动窗口采集至少200个实际新陀螺仪样本校准零偏，车轮运动、噪声太大、总线失败或校准不足会拒绝角度执行，需要静止后重新上电。
3. 先确认零指令、急停、编码器和失能响应，再测试转向。架空轮验证电机方向与停止；真正的陀螺仪角度验证需要车体实际旋转。
4. KEY4进入SIG后识别完整路牌，再按KEY1 ARM。执行时目标方向与角度不随识别分数变化重新设定。看不见牌本身不会中断已经开始且有有效反馈的转向。
5. STM32先返回该动作编号的ACCEPTED/RUNNING，最后返回DONE；FPGA收到正确DONE才退出转向。同一牌持续存在不会重复触发；需连续三次 `?` 清除已消费事件后，再确认新方向。
6. KEY2 STOP、退出SIG、障碍输入、任一反馈通道过期或动作故障均停车并撤销ARM。恢复条件后需重新按KEY1，不自动恢复旧转向。转向结束后若视觉结果已过期，仍保持停车，需要新视觉结果与人工ARM。

实车首先核对物理左转与陀螺仪正Z是否一致。若相反，停止试验，修正传感器坐标/电机方向后再测；不能将仿真90°当作实车方向已验证。轮胎打滑、IMU零偏、执行周期抖动和控制参数都会影响最终角度。

## UART动作协议

115200、8N1、3.3V、二进制字节。所有16位字段高字节在前。

控制仍为11字节，普通速度模式0保持。模式0x10解释如下：

| 下标 | 动作内容 |
|---|---|
| 0 | 7B |
| 1 | 10 |
| 2 | 动作序号，uint8 |
| 3–4 | 相对角度，int16，0.01°；左+9000，右-9000 |
| 5–6 | 最大角速度，uint16，mrad/s；默认700 |
| 7–8 | 前进速度，int16，mm/s；默认0 |
| 9 | 0–8字节XOR |
| 10 | 7D |

FPGA每20ms重复相同序号与参数保活。相同动作已DONE/CANCELLED/FAULT时，重发只返回终态，不能重启动作；相同序号但参数变化报错。运行中另一个序号报BUSY。新序号按uint8模序检查前进；FPGA未ARM时从STM32最后状态同步下一编号。模式0速度帧取消运行中的角度动作，零速度优先。

STM32每50ms在原24字节遥测后追加11字节动作状态：

| 下标 | 状态内容 |
|---|---|
| 0–1 | 7C A1 |
| 2 | 对应动作序号 |
| 3 | 状态：0IDLE，1ACCEPTED，2RUNNING，3DONE，4CANCELLED，5FAULT |
| 4–5 | 累计相对转角，int16，0.01° |
| 6–7 | 剩余角度误差，int16，0.01° |
| 8 | 故障：0无，1参数，2执行超时，3反馈无效/无进展，4失能，5保活/邮箱溢出，6BUSY |
| 9 | 0–8字节XOR |
| 10 | 7E |

ACCEPTED可能在100Hz控制下一拍进入RUNNING，20Hz发送器可能只看到RUNNING；FPGA将两者均作为接受确认。未确认前的DONE、其他序号DONE都不能结束动作。DONE快照不会被随后正常速度帧覆盖。拒绝状态另存完整帧，等待20Hz发送器消费。

## 保护时间与传感器证据

- FPGA首次匹配接受确认限500ms；执行中的**同编号**动作心跳也限500ms，其他编号流量不能续命。整体限8s；常规遥测和动作协议存在性也分别限500ms。
- STM32同编号/同参数保活限300ms；执行总时长限7s。1200ms内误差仍大于3°且累计运动不足0.5°时报告反馈故障。普通速度的原约1.01s丢包保护保留。
- 真正读取的采样须满足：IMU身份正确、±500°/s配置、未休眠、I2C地址/寄存器/读地址均ACK、DRDY新样本、整块读取；启动校准后减零偏。每次读失败立即失效，没有新样本不能刷新时间；超过100ms无新样本失效。不使用编码器或电机命令假装实测转角。
- 本地 `MPU6050.c` 和 `ICM20948.c` 均配置±500°/s。转换用65.5LSB/(°/s)，依据TDK [MPU-6000/6050寄存器手册](https://invensense.tdk.com/wp-content/uploads/2015/02/MPU-6000-Register-Map.pdf)与 [ICM-20948数据手册](https://invensense.tdk.com/wp-content/uploads/2024/03/DS-000189-ICM-20948-v1.6.pdf)。新版官网可能重定向资料地址。
- 任务并发：USART3 IRQ仅投递完整命令；balance拥有控制器并在更新后发布完整11字节缓存；data只复制缓存并在临界区外发UART；IMU任务独占传感器I2C事务。
