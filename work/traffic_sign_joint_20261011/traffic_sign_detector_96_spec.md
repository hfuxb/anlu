# traffic_sign_detector_96

## 功能

模块读取96位四像素RGB流。每帧用四个候选槽跟踪蓝色区域，并按框尺寸、长宽比和蓝色覆盖率筛选近圆形路牌。选中的框在下一帧内按归一化4x4白色像素分布匹配直行、左转或右转箭头。候选不清楚时输出`?`且不输出有效框。

白色模板以样例路牌的空间分布为基础。它不缓存整帧，也不使用完整连通域标号。在线扫描时，每个四像素字只更新首个匹配槽，横向间隙固定为12像素。帧尾为每个候选框合并水平和垂直间距均不超过48像素的候选区。超过四槽时只替换面积不超过64像素的候选槽。

帧尾将相邻候选框合并，再选一个通过尺寸、长宽比和蓝色覆盖率筛选的区域。框合并和候选评分分两拍执行，确保帧尾最后一组蓝像素先写入候选槽；随后用该框采集下一帧的白色格网并分类。结果级同时更新类别与框，避免类别和坐标来自不同候选。结果相对输入帧尾固定延后六拍。

## 左右转补充证据

原20%强白格及原方向分类保留。新增10%弱白格仅用于左右转：弱模板至少命中5格，强模板外白格最多2格，本方向弱命中比反方向至少多1格。四角仍忽略，白色总量下限仍为24。

格子按从上到下、从左到右编号0至15。头部差值为`H=c[1]+c[4]-c[2]-c[7]`；竖杆差值为`V=c[10]+c[14]-c[9]-c[13]`。框面积为A。左转要求`160H>A`且`160V>A`；右转要求`160H<-A`且`160V<-A`。两项证据与弱模板一致时，优先输出对应转向，否则执行原分类。

补充判定还要求当前帧选中候选与取样框的四条边分别满足`24*abs(边差)<=框宽或框高`。取样框、计数、面积和强弱掩码在帧尾同时锁存；下一拍计算有符号差值与模板分数，再下一拍计算方向标志并登记当前帧候选，第三拍从候选寄存器计算框关联，第四拍提交结果。补充判定不保持旧方向，不改变颜色条件，不改变端口。

每格计数饱和至32767；两格和用16位，差值用17位有符号数，乘160前扩展为25位有符号数。左右镜像交换H和V的符号。结果有效与完成脉冲均为一拍，未知结果清除类别和坐标。

## 接口

| 端口 | 方向 | 说明 |
|---|---|---|
| `I_clk` | 输入 | 像素流时钟。 |
| `I_rst_n` | 输入 | 低有效异步复位。 |
| `I_tuser` | 输入 | 帧首有效拍。 |
| `I_tlast` | 输入 | 行末有效拍。 |
| `I_tvalid` | 输入 | 当前四像素字有效。 |
| `I_tdata[95:0]` | 输入 | 四个RGB888像素。 |
| `O_busy` | 输出 | 当前帧正在处理。 |
| `O_done` | 输出 | 帧末结果脉冲。 |
| `O_result_valid` | 输出 | 结果有效脉冲。 |
| `O_result_class[4:0]` | 输出 | `0`未知、`1`左转、`2`右转、`3`直行。 |
| `O_result_ascii[7:0]` | 输出 | `?`、`L`、`R`或`S`。 |
| `O_bbox_valid` | 输出 | 类别明确时为1；未知时立即清0。 |
| `O_x_min/max[10:0]` | 输出 | 与类别同一候选的水平边界。 |
| `O_y_min/max[9:0]` | 输出 | 与类别同一候选的垂直边界。 |
| `O_frame_drop` | 输出 | 固定为低；四个候选槽没有溢出报告路径。 |

## 筛选条件

- 候选宽高为24至512像素。
- 宽高比在2:3至3:2之间。
- 蓝色像素覆盖率至少20%，并不高于70%。低覆盖率会拒绝背景小块，高覆盖率会拒绝没有白色箭头的纯蓝圆形区域。
- 白色形状须与一个方向模板相符；模板外格点和方向分数差限制会拒绝不确定结果。
- 显示框在分类框四周增加4像素边距，并限制在图像范围内。

这些默认值优先减少误识别。实板摄像头的颜色阈值和最小牌面尺寸仍需用传感器原始RGB帧校准。

## 验证

`D:/anlu/rtl/sim/video720/tb_traffic_sign_detector_96.sv` 覆盖三类箭头、人脸色块与高光、错误箭头、截边、遮挡、小/大路牌、分散蓝色块、多候选、空帧及框坐标。

`sim/video720/tb_traffic_sign_joint_replay.sv`以真实照片像素连续回放243个位置，并检查每帧单次结果、类别与坐标、负样本、移走及复位。固定框与牌面偏移模型不能代替实板验收；更大位移的补充判定由候选关联条件禁止。
